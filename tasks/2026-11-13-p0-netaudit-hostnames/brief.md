# 通信の監査で宛先のホスト名を取れるようにする

- 担当: cao-shen（曹参）
- 依頼日: 2026-11-13
- 状態: 完了

## 目的

ユーザーの裁定（2026-11-13 の「通信の扱いの訂正」）で、不要な通信（データ収集、更新の確認など）はすべて止め、要る通信（Claude、git のリモート、Notion）だけを残すことになった。監査はその確かめに使う。ところが今の `scripts/netaudit.ps1` は、試しで DNS のキャッシュ（`Get-DnsClientCache`）が空になり、宛先が IP のままでホスト名が付かなかった。IP だけでは要る・要らないを見分けられないので、ホスト名を取れるようにする。この後に大岡越前守が 0-5（本家の棚卸し）を行う。

## 入力

- docs/user-decisions.md の「通信の扱いの訂正」
- docs/07 の3.3（監査の手順）、2.6（0-5）、3.2 の1・5（起動と PID の集め方）
- `scripts/netaudit.ps1`、`tests/netaudit.tests.ps1`、前の試しの記録（`tasks/2026-11-13-p0-measure-netaudit-tests/handoff-notes.md` の DNS の件、`tasks/2026-11-13-p0-verify-measure-rework/handoff-notes.md`）

## やること

1. DNS のキャッシュが空になる理由を調べる（Chromium が OS の DNS クライアントを通さず自前で名前を引いている、など。出典つき）。
2. ホスト名を取る手段を選んで台本に足す。候補（事実で選ぶ）:
   - Electron・Chromium の `--log-net-log=<file>`（ネットのログ。どのプロセスの通信が載るか、拡張ホストの Node の通信が載るかを確かめる）
   - 拡張ホストなど Node の通信の名前の取り方
   - 逆引き、TLS の SNI など
   - 管理者の権限が要る手段（`pktmon`、DNS クライアントのイベントログを有効にするなど）は、要る理由を書いて報告するだけにする。自分で有効にしない。
3. 出力の表に、宛先のホスト名と、それを取った手段の列を足す。許した宛先の一覧（`records/network-allowlist.json` の形。docs/07 の3.3 の5）と照らせる形にする。
4. 単体テストを足して走らせ、公式の zip（`C:\b\p0\data\upstream-default` の環境）で60秒ほど一度だけ試し、ホスト名が付くことを確かめる。

## 守ること

- 書き込みは自分の書き込み先（`tests/`・`tasks/`・`C:\b\`、自分の台本 `scripts/netaudit.ps1`）だけ。蒙恬の台本は書き換えない。
- 別の曹参（タスク `2026-11-13-p1-smoke`）が並行して `tests/smoke/` を作っている。そこには触れない。
- 普段使いのエディタのデータ（`%APPDATA%\Code`、`%USERPROFILE%\.vscode`、`~\.vscode-oss`）に触れない。起動した PID の木だけを止める。
- ネットのログには秘密（トークンなど）が載ることがある。ログはリポジトリの外（`C:\b\`）に置き、記録に写すのはホスト名と回数だけにする。
- 10分の本番の監査（0-5）はまだ行わない。
