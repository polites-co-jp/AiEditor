# Phase 1: 本家 1.146.0 を無改造で Windows でビルドし、zip にする

- 担当: meng-tian（蒙恬）
- 依頼日: 2026-11-13
- 状態: 依頼中

## 目的

機能の削除（Phase 2）に入る前に、本家のタグを無改造のままこの PC でビルドし、zip にして起動できることを確かめる。所要時間とディスクを記録し、毎週の取り込みで回せる重さかをユーザーが判断できるようにする（docs/07 の4節の関門）。

## 入力

- docs/07 の4節（Phase 1）、docs/02 の4節（ビルドの流れ）・5節（Windows のビルド環境）・7節
- docs/user-decisions.md の 2026-11-13 の「計測と通信の監査をやめる」（メモリの計測はしない。ピークのメモリも測らない）
- `tasks/2026-11-13-p0-close/design-changes.md` の4節（Phase 1 へ持ち越す点）
- 基準の版: 1.146.0（commit `69047191fc427f2f92828279aae1d90d8eeda7ab`）。`C:\b\p0\vscode-1.146.0\`（公式の zip を展開したもの）は比べる相手として読んでよい
- `local.json` の `buildRoot`（既定 `C:\b\`）

## やること

1. **環境を確かめる**: docs/02 の5節の表の各項目（Git、タグの `.nvmrc` の Node.js の版、Python と setuptools、Visual Studio Build Tools と wiki が挙げるコンポーネント、pnpm か npm か）が入っているか、版は何かを調べる。
   - 足りないものがあれば、そこで止める。ユーザーが入れる手順（winget のコマンド、管理者の権限が要るか、所要時間の見込み）を `env-check.md` に書いて報告する。自分で入れない。
2. **足りていれば**、次を行う。
   1. 常設の clone を `C:\b\vscode` に作り、`git worktree add C:\b\wt\1.146.0 1.146.0`。commit が上の値と一致することを確かめる。
   2. 本家のタグの手順で依存を入れ、`vscode-win32-x64-min` でパッケージ化する。
   3. 型検査だけを走らせる script を選ぶ（docs/02 の4節の5）。
   4. 出力を zip にする（`tar.exe` で作れるか。作れなければ何が要るか）。
3. **記録する**（docs/07 の4節の3。ピークのメモリは除く）: 各手順の所要時間、ディスク（作業ツリー、キャッシュ、出力）、使ったパッケージマネージャー、型検査の script の名前、実行ファイルの名前、出力の中の `resources\app\` の置き場所（公式の zip は `<commit10>\resources\app\`）、ユーザーのデータと拡張と `argv.json` の実際の場所、`tar.exe` で zip が作れたか。
4. 失敗したら、本家の案内（`git clean -xfd`、node-gyp のキャッシュ）を試し、それでもだめなら誤りのログの要点を残して止める。

## 守ること

- 書き込みは自分の書き込み先（`scripts/`・`tasks/`・`C:\b\` など）だけ。`records/` は大岡越前守が書く。
- 普段使いのエディタのデータ（`%APPDATA%\Code`、`%USERPROFILE%\.vscode`、`~\.vscode-oss`）に触れない。ビルドしたものを起動して確かめるときは、`VSCODE_PORTABLE` で置き場所を分ける（docs/07 の3.2 の1 と同じ注意。子のプロセスから `ELECTRON_RUN_AS_NODE` などを外す）。
- 許可に無いコマンドが要るときは、走らせずに「何のために何が要るか」を報告する。
- 本家のコードを変えない（無改造）。
