# 00 概要

## 1. 目的

本家 VS Code のソース（Code - OSS、MIT）から、ユーザー1人が Claude Code でコーディングするのに要る機能だけを残したエディタを作る。

- Windows 専用。配布は zip を展開するだけ。インストーラーと署名は作らない。
- 省メモリ: 数値の目標は置かない。やるべき削減をやる。計測はせず、減ったかはユーザーが使って判断し、減らなければ本家を使う（裁定 2026-11-13。それまでは「本家と同じ条件で測って少しでも少なければ合格」）。
- 不要な機能は**コードごと消す**。設定で隠すだけでは済ませない。段階的に全部消す。
- 本家には自動で追従しない。新版が出たら Notion の ToDo に「取り込みの検証」が入る。取り込むかは、毎週 Claude（`claude -p`）に検証させて、ユーザーが決める。

## 2. 使う場面（1日の流れ）

| 時刻の例 | 場面 | エディタが担うこと |
|---|---|---|
| 朝 | Notion の ToDo に「取り込みの検証: 本体 1.147.0（セキュリティ修正あり）」が入っている | 更新の検知のプログラムが、夜のうちに ToDo を足している（[06](06-update-watch-and-take-in.md)） |
| 朝 | 取り込みのスクリプトを起動し、ビルドと検証を待つあいだは今の版で仕事をする | 版ごとのフォルダに新しい版を作る。今の版には触らない |
| 午前 | リポジトリを開き、Claude Code のパネルで「この関数にテストを足して」と頼む | 拡張のパネル、ワークスペースの信頼、選択範囲の共有、差分の表示（本家の差分ビュー） |
| 午前 | 提案された差分を差分ビューで見て、採る | 差分ビュー、エディタの分割、Sublime Text のキー割り当て |
| 昼 | 統合ターミナルで `claude` を動かし、テストを流す | ターミナル、タスク実行、問題パネル（Claude Code が診断を読む） |
| 午後 | 全文検索で呼び出し元を探し、置換する。Markdown の設計メモをプレビューで読む | 全文検索・置換、Markdown プレビュー、画像・PDF のプレビュー |
| 午後 | git で差分を確かめてコミットする | git（組み込みの git 拡張。Git for Windows が要る） |
| 夕方 | 取り込みの判定（合格）を読み、エディタを閉じて新しい版へ切り替える | 切り替えのスクリプト。不具合が出たら前の版へすぐ戻す |
| 別の PC | 同じ設定・キー割り当て・スニペットで作業する | Notion の設定ページとの同期（[05](05-settings-sync.md)） |

## 3. 方針の要約

1. ビルドリポジトリ方式: 本家を fork せず、本家の固定タグに「削除の単位」とパッチを当て直してビルドする、小さなリポジトリを持つ。取り込みは「タグを書き換えて当て直す」作業になる（[02](02-repository-and-build.md)）。
2. 削除の単位: 消す機能ごとに、独立した「削除の単位」（消すパスの一覧＋残るファイルへの小さなパッチ＋検査）を作る。単位ごとに有効・無効を切り替えられ、壊れたら単位ごとに戻せる（[03](03-removal-design.md)）。
3. 順序: 組み込み拡張と軽い部分（段階 A・B）を先に消して試作する。動くことを確かめながら、本体の深い部分（段階 C: AI、デバッガ、リモート、ノートブックなど）を1単位ずつ消す。
4. 同梱する拡張: Open VSX から版とハッシュを固定して取り、発行元・ハッシュ・署名・公式配布物との一致を確かめてから、本体とは別の周期で入れる（[04](04-bundled-extensions.md)）。
5. 自前の組み込み拡張: 既定の設定・Sublime のキー割り当て・固定のテーマは `mydist`（起動しない宣言だけの拡張）、Notion との設定の同期は `notion-sync` が持つ。
6. 更新の検知: Windows のタスクスケジューラで毎日動くプログラムが、本体と同梱拡張の新版を調べ、自分で Notion API を呼んで ToDo を書く（[06](06-update-watch-and-take-in.md)）。

## 4. ユーザーの裁定（2026-11-12）

ここに挙げたことは、ユーザーが決めたこと。設計はすべてこれに従う。違う案は [08](08-risks-and-open-items.md) の「別案」に分けた。

### 4.1 構想

- VS Code から多くの機能を削り、必要な機能だけを取り入れる。Claude によるコーディングに特化した、省メモリのエディタにする。
- 最初に挙げた機能: 基本のテキスト編集、ショートカットの編集、Sublime Text のキー割り当て、git 操作、Claude Code 拡張、日本語化、ファイルエクスプローラー、ターミナル。

### 4.2 裁定の一覧

| 論点 | 裁定 |
|---|---|
| 対象 OS | Windows のみ |
| 本家への追従 | 自動では追従しない。新版（特にセキュリティ修正）が出たことだけ通知する。取り込むかは、そのつど Claude に検証させて決める |
| 残す・入れる機能（追加分） | 全文検索・置換、差分ビュー、言語機能（補完・エラー表示）、Markdown プレビュー、設定の同期、画像・PDF プレビュー、問題パネル・タスク実行 |
| 削る機能 | 拡張の追加インストール（同梱した拡張だけで動く固定構成）、デバッガ、リモート開発（SSH・WSL・コンテナ）、Jupyter ノートブック |
| 省メモリの目標 | 数値の目標は定めない。やるべき削減をやる。計測はせず、減ったかはユーザーが使って判断する（2026-11-13 に改めた） |
| 補完・エラー表示の対象言語 | TypeScript / JavaScript、Python、HTML / CSS / JSON、CSV、.env、sh、PowerShell。cmd とそれ以外の言語は色付けだけ |
| 本家の AI 機能（Copilot・チャットパネル） | 削る。ただし Claude Code 拡張が依存する部分があれば特定して残す |
| テレメトリ・不要な外部通信 | 削る。送り先と鍵を入れず、送信を担う部品を何もしない実装に差し替える。不要な通信（データ収集、更新の確認など）はすべて止め、要る通信（Claude、git のリモート、Notion）だけを残す（2026-11-13） |
| 本家の新版の通知 | Notion の ToDo に「取り込みの検証」を足す。本体に加え、同梱する拡張（特に Claude Code 拡張）の新版も対象。通知だけにする（修正差分の試しの当て直しの結果は添えない） |
| 取り込みの検証の頻度 | 本家の新版ごとに、毎週すべて検証する |
| 新しい版への入れ替え | Claude の判定を見て、ユーザーが自分で入れ替える |
| ToDo の書き込みの経路 | 更新の検知のプログラムが、自分で Notion にアクセスして ToDo を書く |
| 画面の部品で残すもの | ミニマップ、エディタの分割・複数ウィンドウ |
| 画面の部品で削るもの | アウトライン・パンくずリスト、テーマの切り替え（固定のテーマ1つ） |
| 固定するテーマ | Light Modern |
| その他残すもの | コマンドパレット、スニペット・自動整形、タイムライン・ローカル履歴、ワークスペースの信頼・制限モード |
| 同梱する拡張の入手 | Open VSX から取得し、版とハッシュを固定して台帳に記録する。発行元と公式配布物の一致も確かめる。更新は「通知 → Claude が検証 → 差し替え」の順 |
| Python の言語機能 | basedpyright |
| PDF プレビュー | tomoki1207.pdf を同梱する。不具合が出たら差し替えを検討する |
| 外部ツール（ShellCheck、PowerShell 7 など） | エディタには同梱しない。別途インストールする前提で、入れる手順を書く。無ければその言語は色付けだけ |
| 設定の同期 | Notion に設定ページを作り、そこを同期先にする。本家の Settings Sync は使わない |
| 「削る」の意味 | コードごと消す |
| 消す範囲と順序 | 段階的に全部消す。まず組み込み拡張と軽い部分を消して試作し、動くことを確かめながら本体の深い部分（AI・デバッガ・リモート・ノートブックなど）も順に消す。壊れたら戻せるようにする |
| Claude Code 拡張の依存の調べ方 | 公開されている設定情報（manifest）・ファイル一覧と、実機の動作だけで判断する。圧縮されたコードの中身は調べない |
| 配布の形 | zip を版ごとのフォルダに展開し、参照先を切り替える。前の版へすぐ戻せる |
| 名前・アイコン | 後で決める。資料では仮の名前を使う。Microsoft・Visual Studio・Claude の名称とロゴは使わない |
| 予備案（VSCodium の zip の後処理で運用） | ソースのビルドが重すぎたときに改めてユーザーに諮る |

### 4.3 裁定（2026-11-12、この設計資料の論点への回答）

| 論点 | 裁定 | 反映した箇所 |
|---|---|---|
| 拡張 API の入口（`vscode.debug`・`vscode.notebooks`・`vscode.lm`・`vscode.chat` など） | 入口は何もしない実装にして残し、中身のコードは消す | [03](03-removal-design.md) の2節の4 |
| 裁定に無かった機能 | ターミナルの入力候補（`terminal-suggest`）は消す。テスト（`contrib/testing`）とコメント（`contrib/comments`）は残す。使って重ければ改めて諮る | [01](01-requirements.md) の1節・3節、[03](03-removal-design.md) の A-7 |
| .env の拡張 | Phase 0 で `dotenv.dotenv-vscode` と `weixu.wx-vsce-dotenv` を試し、エラー表示を持つほうを採る | [01](01-requirements.md) の4節、[07](07-phases.md) の 0-3 |
| 拡張の新版を寝かせる期間 | 公開から72時間未満の版は、セキュリティ修正でない限り入れない | [04](04-bundled-extensions.md) の4節の4 |
| 更新の検知の Notion トークン | DPAPI で暗号化したファイルに置く | [06](06-update-watch-and-take-in.md) の2.4 |
| Notion のインテグレーション | 2つに分ける。設定の同期用は設定ページだけ、更新の検知用は ToDo データベースだけに接続する | [05](05-settings-sync.md) の7節、[06](06-update-watch-and-take-in.md) の2.4 |
| 取り込みの結果の書き戻し | 書き戻す。ToDo の本文に判定の要約を足し、状態を `In progress` にする | [06](06-update-watch-and-take-in.md) の4節 |
| ToDo の優先度・期限 | セキュリティ修正あり: 優先度「高」・期限は翌日。それ以外: 期限はすべて7日後で、優先度は本体と Claude Code 拡張が「中」、ほかの拡張が「低」 | [06](06-update-watch-and-take-in.md) の2.3 |
| 版のフォルダの場所 | 設定で変えられるようにする（既定値の扱いは設計で決める） | [02](02-repository-and-build.md) の6節（PC ごとの設定ファイル `local.json`） |
| 言語パックが本体より古い点 | 未訳の部分が英語になるのを受け入れる。目立つなら改めて諮る | [04](04-bundled-extensions.md) の7節 |
| Microsoft 発行の拡張（日本語パック・PowerShell）を Open VSX から使う法的な確認 | 個人利用として、確認せずに使う。リスクはユーザーが受け入れる | 5節、[04](04-bundled-extensions.md) の7節、[08](08-risks-and-open-items.md) の1節 |

## 5. 守るべき前提

- ライセンスと商標: 本家のソースは MIT（"Copyright (c) 2015 - present Microsoft Corporation"）。著作権表示と許諾文を残す [一次] https://github.com/microsoft/vscode/blob/main/LICENSE.txt 。ロゴと製品名は MIT の対象外 [一次] https://github.com/microsoft/vscode/wiki/Differences-between-the-repository-and-Visual-Studio-Code 。
- Claude Code 拡張の条件: "The Claude Code binary must not be modified. Claude Code must be installed and run as published by Anthropic" [一次] https://code.claude.com/docs/en/legal-and-compliance 。VSIX は改変せず、本体の正規の手順（`--install-extension`）で入れる。名称・ロゴをエディタの名前に使わない。
- Marketplace を使わない: Marketplace の規約は対象を Visual Studio 系の製品に限る [一次] https://cdn.vsassets.io/v/M264_20251020.18/_content/Microsoft-Visual-Studio-Marketplace-Terms-of-Use.pdf 。拡張は Open VSX から取る。Microsoft 発行の拡張（日本語パック、PowerShell）を Open VSX 経由で使うことが規約に触れないかは、文書から断定できない。裁定により、個人利用として法的な確認をせずに使い、そのリスクはユーザーが受け入れる（4.3）。
- Pylance は使えない: "can only be used on official Microsoft builds of Visual Studio Code" [一次] https://github.com/microsoft/pylance-release/blob/main/FAQ.md 。Python は basedpyright。
- 秘密の扱い: Notion のトークンはリポジトリにも settings.json にも置かない（[05](05-settings-sync.md)、[06](06-update-watch-and-take-in.md)）。
- API キーを使わない: 取り込みの検証などの LLM の処理は、ユーザーがログインした Claude Code の CLI を `claude -p` で起動する。スクリプトは子プロセスの環境変数から `ANTHROPIC_API_KEY` を外す。

## 6. 用語

| 用語 | 意味 |
|---|---|
| 本家 | microsoft/vscode のリポジトリと、そのタグ |
| ビルドリポジトリ | このエディタのリポジトリ。本家のソースは持たず、タグ・削除の単位・パッチ・上書き・台帳・スクリプトを持つ |
| 作業ツリー | 本家の常設 clone から、タグごとに `git worktree` で取り出す使い捨てのソース |
| 削除の単位 | 1つの機能を消すための束。消すパスの一覧、残るファイルへのパッチ、検査からなる（[03](03-removal-design.md)） |
| 段階 A / B / C | 削除の順序。A は組み込み拡張、B は軽い部分、C は本体の深い部分 |
| 台帳 | `extensions.lock.json`。同梱する第三者の拡張の版・ハッシュ・検証の記録 |
| mydist | 自前の組み込み拡張。既定の設定・キー割り当て・テーマを宣言だけで持つ（`main` なし） |
| notion-sync | 自前の組み込み拡張。Notion の設定ページと設定ファイルを同期する |
| 取り込み | 本家の新しいタグ、または拡張の新しい版を、検証してから採ること |
| 判定 | 取り込みのときに `claude -p` が出す採否（合格・条件付き・不合格）と理由 |
